# MyLog 上线检查清单

照着 [02-部署.md](02-部署.md) 部署时，用这份清单逐项打勾。每一项都写了**怎么确认**，结果对得上再往下走。命令默认在服务器的 `/opt/mylog` 目录下执行。

> 在 GitHub 上打开这个文件可以直接看到勾选框；也可以复制到自己的笔记里勾选。

---

## 一、开始之前

- [ ] **服务器**：Ubuntu 22.04 / 24.04，至少 1 核 1G，磁盘剩余 10G 以上
  确认：`lsb_release -d; nproc; free -h; df -h /`
- [ ] **域名解析**：A 记录指向服务器公网 IP
  确认：在自己电脑上运行 `ping 你的域名`，显示的 IP 是服务器 IP
- [ ] **备案**（仅中国大陆服务器）：域名已完成 ICP 备案，否则 80/443 会被云厂商拦截
- [ ] **安全组**：只放行 22、80、443；**没有**放行 8787
  确认：在云厂商控制台的安全组规则里逐条看一遍
- [ ] **云数据库**：MySQL 8.0，和服务器在同一个地域、同一个 VPC；库 `mylog` 的字符集是 utf8mb4
  确认：云数据库控制台的实例详情、数据库管理页
- [ ] **数据库账号**只对 `mylog` 库有读写权限，不是管理员账号
  确认：控制台「账号管理」里看这个账号的授权
- [ ] **数据库白名单**只有服务器的内网 IP，**没有** `0.0.0.0/0`；没有申请外网地址（或外网地址不在用）
  确认：控制台「白名单 / 安全组」和「数据库连接」页
- [ ] **自动备份**已打开，每天一次，保留 7 天以上
  确认：控制台「备份恢复」页能看到备份策略和最近的备份记录
- [ ] **SSH 用密钥登录**，并关掉密码登录
  确认：`grep -E '^(PasswordAuthentication|PermitRootLogin)' /etc/ssh/sshd_config` 显示 `PasswordAuthentication no`
  ⚠️ 改之前先确认用密钥能登录，否则会把自己锁在外面
- [ ] **自动安装系统安全更新**
  确认：`apt-get install -y unattended-upgrades && dpkg-reconfigure -plow unattended-upgrades`

## 二、安装与配置

- [ ] Docker 已安装并开机自启
  确认：`docker --version && docker compose version && systemctl is-enabled docker` → 最后一行是 `enabled`
- [ ] 代码在 `/opt/mylog`，是 `main` 分支的最新版本
  确认：`git -C /opt/mylog log --oneline -1`，和 GitHub 上 `main` 的最新提交一致
- [ ] `.env` 里的 `DATABASE_URL` 已改成云数据库的内网地址和账号密码（不是示例里的「改成…」）
  确认：`grep -E '^DATABASE_URL=mysql://' .env | grep -v 改成 | wc -l` → 显示 `1`
- [ ] 数据库密码是随机生成的长密码，密码里的特殊符号已做 URL 编码
- [ ] `.env` 只有 root 能读
  确认：`stat -c '%a' .env` → 显示 `600`
- [ ] 把数据库账号密码另外存一份在密码管理器里（恢复备份时要用）

## 三、启动与自检

- [ ] 应用容器在运行且健康，能连上云数据库
  确认：`docker compose ps` → `app` 是 `healthy`（第一次启动要等 1–2 分钟）；如果是 `Restarting`，看 `docker compose logs app`，对照 02-部署.md 的报错表
- [ ] 数据表已在云数据库里自动建好
  确认：在云数据库控制台登录 `mylog` 库，能看到 `users`、`sessions`、`tasks`、`days`、`meetings` 五张表
- [ ] 应用正常响应
  确认：`curl -s http://127.0.0.1:8787/api/health` → `{"ok":true}`
- [ ] 应用端口**没有**对外开放
  确认：`ss -tlnp | grep -E ':8787'` → 只有 `127.0.0.1:8787`，没有 `0.0.0.0` 或 `*`
  > 说明：Docker 映射的端口不受 ufw 防火墙管，所以这一项必须看实际监听地址
- [ ] 应用以普通用户运行，不是 root
  确认：`docker compose exec app whoami` → `node`
- [ ] 启动日志没有报错
  确认：`docker compose logs app | grep -iE 'error|fail'` → 没有输出

## 四、域名与 HTTPS

- [ ] Nginx 配置里的域名已经替换成你自己的
  确认：`grep server_name /etc/nginx/sites-enabled/mylog`
- [ ] Nginx 配置检查通过
  确认：`nginx -t` → `syntax is ok` 和 `test is successful`
- [ ] HTTPS 证书申请成功
  确认：浏览器打开 `https://你的域名`，地址栏显示锁形图标
- [ ] HTTP 会自动跳转到 HTTPS
  确认：`curl -sI http://你的域名 | head -1` → `301`
- [ ] 证书会自动续期
  确认：`certbot renew --dry-run` → 最后显示 `succeeded`
- [ ] 登录失败次数限制按真实 IP 计算（`docker-compose.yml` 里 `TRUST_PROXY: "1"`）
  确认：`docker compose exec app printenv TRUST_PROXY` → `1`

## 五、功能验证（在浏览器里）

- [ ] 打开 `https://你的域名`，页面正常显示，没有白屏
- [ ] 在「设置」里注册账户，侧边栏底部显示「已同步 · 刚刚」
- [ ] 添加一件带时间的事（比如「5分钟后的时间 测试提醒」），浏览器弹出通知授权时点“允许”；到点收到系统通知
- [ ] 在**另一台设备**（比如手机浏览器）用同一账户登录，能看到刚才添加的事
- [ ] 在手机上完成这件事，回到电脑上点「立即同步」，显示为已完成
- [ ] 输错密码时提示「邮箱或密码不对」
- [ ] 刷新页面、关掉浏览器再打开，数据都还在

## 六、备份

- [ ] **云数据库的自动备份**已经有至少一份成功的记录
  确认：控制台「备份恢复」→ 备份列表里有今天或昨天的备份，状态是成功
- [ ] **试着恢复一次**（只有恢复成功过的备份才算数）
  确认：在控制台用最近的备份「恢复到新实例」或「恢复到新库」（不要覆盖 `mylog` 库），登录恢复出来的库，执行 `SELECT COUNT(*) FROM tasks`，条数大于 0、和你账户里的任务数大致对得上（已完成和已删除的也算在内）；看完把临时实例 / 库删掉，避免多付费
- [ ] （可选）服务器上再多留一份导出：手动跑一次 `./deploy/backup.sh` 成功
  确认：显示「备份完成」，`ls -lh /var/backups/mylog/` 能看到文件且大小不是 0
- [ ] （可选）导出已加入定时任务
  确认：`crontab -l | grep backup.sh`

## 七、重启演练

- [ ] 重启服务器后，一切自动恢复
  确认：`reboot`，等 2 分钟重新登录后：`docker compose ps` 显示 `app` 是 `healthy`，浏览器能正常打开、数据都在

## 八、上线之后

- [ ] GitHub 仓库的默认分支改成 `main`（Settings → General → Default branch）
- [ ] 记下出问题时的回退办法：
  - **新版本有问题**：`git -C /opt/mylog log --oneline` 找到上一个能用的版本，`git checkout <提交号> && docker compose up -d --build`
  - **数据出问题**：先 `docker compose stop app`，在云数据库控制台按时间点把 `mylog` 库恢复到出问题之前，确认后再 `docker compose start app`
- [ ] 一周后回来看一眼：
  - 磁盘：`df -h /`，使用率不超过 80%
  - 备份：云数据库控制台的备份列表每天都有新记录（用了 `backup.sh` 的话，`ls -lh /var/backups/mylog/` 每天也有新文件）
  - 日志：`docker compose logs --since 24h app | grep -ciE 'error'`，数量很少或为 0
